## Tujuan
Semua akses WordPress terjadi di `server/` lewat satu klien baca-saja; komponen hanya melihat tipe domain, bukan struktur mentah REST.

## Node Figma
`n/a` (task data).

## Di luar scope
Halaman/komponen UI, penulisan ke WordPress, iklan (ADS-001/002), widget sosial (SOC-001), plugin WordPress.

## Kriteria penerimaan (draf; final setelah DISC-002)
1. `server/services/wp-client.ts`: base URL dari env server (`NUXT_WP_BASE_URL`), bukan dari input pengguna; timeout dan retry terbatas; hanya `GET`.
2. Tipe domain `Article`, `Category`, `MediaAsset` (PRD §6) di `app/types`; mapper memetakan REST → tipe domain; `_embedded` tidak bocor.
3. Hanya `status=publish`; draft/private tidak pernah terpapar.
4. `_fields` dipakai untuk memangkas payload; header `X-WP-Total`/`X-WP-TotalPages` dibaca bila ada daftar berhalaman.
5. Validasi `slug`, `page`, `q` (PRD §3.5: 2–100 karakter) di `server/utils`.
6. Sanitasi HTML isi artikel di server (hapus `script`, event handler, `javascript:`; embed hanya allowlist).
7. Penanganan error: 404, daftar kosong, timeout, WordPress mati → respons terkontrol tanpa stack trace/path/env.
8. Tidak ada secret di `runtimeConfig.public`, log, atau bundel klien.

## Rencana tes (QA)
Disusun setelah BLOCKED dibuka; wajib mencakup: sukses, 404, timeout, kosong, gambar/kredit hilang, artikel dihapus, draft tak terlihat, WP mati, XSS di konten uji, `slug`/`q` berbahaya (`../`, URL penuh, panjang), `grep` bundel klien untuk URL/secret internal.

## File yang boleh disentuh
`server/services/**`, `server/utils/**`, `server/api/**` (handler tipis), `app/types/**`, `tests/unit/**`, `.env.example` (hanya placeholder), `nuxt.config.ts` (hanya `runtimeConfig` server) **[APPROVAL]**, `package.json` (sanitizer) **[APPROVAL]**.
