## Tujuan
Fungsi layanan membaca WordPress lewat REST bila `NUXT_WP_BASE_URL` diisi; tanpa env, tetap fixture (uji, QA, dev tanpa WordPress). Komponen, halaman, dan bentuk respons `/api/*` tidak berubah.

## Di luar scope
Penulisan ke WordPress, kredensial/draft (`NUXT_WP_USER`), iklan (ADS), widget sosial dari WP, SEO plugin, webhook purge, pengalihan 301, UI baru, dependensi baru.

## Keputusan PM
1. **Sumber data.** `server/utils/wp-client.ts` (baru): `GET` saja; base URL dari `useRuntimeConfig().wpBaseUrl` (env `NUXT_WP_BASE_URL`, privat, tidak di `public`); hanya origin `https://host[:port]` (juga `http://localhost` / `127.0.0.1` untuk dev); tidak valid/kosong = fixture. Ambil `posts?_embed&status=publish&per_page=100` berhalaman (baca `X-WP-TotalPages`, maks. 10 halaman) dan `categories?per_page=100&_fields=id,slug,name,parent,count`. Hasil dipetakan ke tipe `WpPost` yang sama dengan fixture, sehingga logika yang ada (urutan, kategori, Terpopuler, Ruang Visual, Berita Terkait, pencarian) tidak berubah. `_fields` hanya untuk kategori; posts membutuhkan `_embed`.
2. **Cache dan kegagalan.** Cache memori per proses TTL 60 detik (konstanta `WP_CACHE_TTL_MS` di `app/config/`), satu permintaan bersamaan (single-flight), timeout 8 detik, 1 retry. Gagal (timeout, 5xx, JSON rusak, > 20 MB): pakai cache lama bila ada; bila tidak, `/api/*` membalas 502 dengan pesan tetap "Sumber data tidak tersedia." (tanpa stack, path, URL, env). Halaman Beranda tetap tampil tanpa section yang kosong.
3. **Fungsi layanan jadi `async`** (hanya tanda tangan; isi/aturan sama); handler `server/api/**` menambah `await`. `getCategories()` = 9 kategori resmi (`OFFICIAL_CATEGORY_SLUGS`, urutan menu) yang ADA di WordPress; yang belum ada dilewati (menu menyesuaikan). Kategori non-resmi tetap teks.
4. **Pemetaan.** `authorLabel` selalu `IniSumedang` (jangan tampilkan nama pengguna WordPress); `alt` gambar = `alt_text` atau judul bila kosong; kredit foto = caption media (teks polos); ringkasan = `excerpt.rendered` (tanpa tag, entitas didekode); `date_gmt` + `Z`; gambar lewat `safeImageUrl` dengan host WordPress dari base URL sebagai SATU-SATUNYA host https tambahan (dan penyanitasi isi memakai host yang sama lewat `imageHosts`); `IMAGE_ALLOWED_HOSTS` statis tetap kosong. Isi artikel SELALU lewat `sanitizeBodyHtml`.
5. **Konfigurasi.** `nuxt.config.ts`: hanya tambah `runtimeConfig.wpBaseUrl: ''` **[APPROVAL pemilik saat commit]**. `.env.example` sudah memuat `NUXT_WP_BASE_URL` (jangan membaca/ubah `.env` asli). Tanpa dependensi baru; tidak ada secret.
6. **Dev.** Pemilik mengisi `.env` lokal `NUXT_WP_BASE_URL=https://ini-sumedang.local`; uji Fullstack/QA memakai env baris perintah, bukan `.env`.

## Kriteria penerimaan
1. Env kosong/tidak valid: perilaku dan seluruh uji lama identik (fixture). Env terisi: Beranda, Detail, kategori, `/cari`, sidebar, hero, Ruang Visual membaca WordPress tanpa perubahan tampilan.
2. Hanya `GET`; tidak ada kredensial; draft/private tidak muncul (`status=publish`).
3. WordPress mati/lambat/500/JSON rusak: cache lama dipakai, atau 502 pesan tetap; tanpa stack/path/URL/env di respons dan konsol HTML; Beranda tidak crash.
4. Konten berbahaya dari WordPress (`<script>`, `onerror`, `javascript:`, judul ber-HTML, `source_url` aneh) tidak tereksekusi/tidak dirender (uji dengan respons tiruan di salinan).
5. Slug, `halaman`, `q` tetap divalidasi seperti sekarang; `__NUXT_DATA__`/bundel klien tidak memuat base URL WordPress.
6. `lint`, `typecheck`, `npm test` (uji murni untuk validasi base URL, penggabungan halaman, cache/stale, pemetaan), `build` kode 0; `v-html=` satu baris.

## Catatan
- Setelah gagal memuat, pemuatan ulang menunggu 10 detik (`WP_FAILURE_BACKOFF_MS`, usulan Fullstack) agar WordPress yang mati tidak membuat tiap permintaan menunggu timeout 8 detik × 2.
- URL gambar memuat host WordPress (perlu agar gambar tampil), jadi host itu muncul di `__NUXT_DATA__`; yang tidak ada hanya konfigurasi `wpBaseUrl`/base URL sebagai nilai. Gambar hanya lolos bila base URL `https` tanpa port; gambar tanpa `width`/`height` dianggap tanpa gambar.
- Kategori/tag dummy WordPress masih acak (belum 9 kategori resmi): menu dan halaman kategori akan menyesuaikan sampai data dirapikan pemilik.
