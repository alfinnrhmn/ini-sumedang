## Tujuan
Kategori, label, dan tag yang dibuat di WordPress muncul di Nuxt: menu, laci, footer, halaman kategori, label kartu/hero/Detail, section Beranda, dan tag di Detail. Daftar 9 kategori di kode tidak lagi menjadi acuan saat sumbernya WordPress.

## Di luar scope
Halaman tag, urutan menu lewat plugin, perubahan desain, WordPress tulis, iklan, widget sosial.

## Keputusan PM
1. **Daftar kategori.** Mode WordPress: `getCategories()` = SEMUA kategori WordPress kecuali `uncategorized`, `ruang-visual`, dan anak-anak `ruang-visual`; urutan = id naik (urutan pembuatan). Mode fixture tidak berubah (9 kategori resmi, urutan menu). Slug `berita` tetap = Beranda (E1: tautan `/`, `/kategori/berita` 308) bila ada. Halaman `/kategori/<slug>` valid untuk slug yang ada di daftar itu (selain itu 404).
2. **Satu sumber di klien.** `categoryLink(slug)` tidak lagi memakai `OFFICIAL_CATEGORY_SLUGS`; ia memakai daftar dari `/api/categories` (satu permintaan, sudah dipakai header; dibagikan lewat `useState`/data Nuxt yang tersedia saat SSR sebelum halaman merender, tanpa hydration mismatch). Kategori yang tak ada di daftar (anak Ruang Visual, `uncategorized`) tetap teks biasa. Hapus `OFFICIAL_CATEGORY_SLUGS` dan duplikasinya (menutup PRD §13 butir 3).
3. **Section Beranda dinamis.** `HOME_SECTIONS` menjadi urutan PREFERENSI: section = kategori dari daftar itu yang ada dan punya ≥ 1 artikel terbit; diisi dulu menurut urutan preferensi (judul konfigurasi bila slug cocok), lalu kategori lain yang tak kosong menurut urutan daftar (judul = nama WordPress, selain `berita`), maksimum 4 section, 4 artikel per section. Mode fixture harus tetap IDENTIK (sepak-bola, nasional, bisnis-teknologi, otomotif). Posisi: Ruang Visual setelah section pertama; widget sosial mobile setelah section ke-3 (atau terakhir bila kurang dari 3); iklan section pertama seperti sekarang. `/api/articles/by-category` menerima slug kategori mana pun dari daftar (batas limit tetap).
4. **Menu, laci, footer** menampilkan semua kategori daftar; bila > 9, menu desktop boleh membungkus ke baris berikutnya (tanpa overflow horizontal dan tanpa menimpa konten); laci dan footer mendaftar semuanya.
5. **Tag.** Tag artikel WordPress ditampilkan di Detail sebagai baris label teks (bukan tautan; tidak ada halaman tag) di bawah isi dan di atas "Bagikan", komponen kecil baru dengan token yang ada. Tag `terpopuler` (tag fungsional, `POPULAR_TAG_SLUG`) TIDAK ditampilkan, termasuk sebagai label kedua di kepala artikel (label kedua = tag tampil pertama). Tanpa tag tampil: baris tidak dirender.
6. Tanpa dependensi, token, font baru; `nuxt.config.ts` tidak berubah; sanitasi dan validasi lama tetap.

## Kriteria penerimaan
1. WordPress Local nyata (8 kategori acak, 4 tag acak): menu/laci/footer memuat 8 kategori itu (nama WordPress, tanpa Uncategorized); tiap `/kategori/<slug>` 200 dengan artikelnya (atau keadaan kosong); label kartu/hero/Detail menaut ke kategori yang ada; section Beranda terisi dari kategori tak kosong; tag tampil di Detail (tanpa `terpopuler`); tanpa galat konsol.
2. Mode fixture (env kosong): tampilan identik HEAD (rect 1440/402 Beranda, Detail, kategori, `/cari`; `/api/*` identik); semua uji lama lulus.
3. Server tiruan: 15+ kategori (menu membungkus tanpa overflow), nama ber-HTML/entitas, kategori kosong, `uncategorized`, `ruang-visual` + anak, tanpa kategori sama sekali (menu tidak dirender, Beranda tidak crash), slug tak valid (404).
4. SSR: tautan kategori ada di HTML server (bukan baru muncul setelah hidrasi); tanpa hydration warning.
5. `lint`, `typecheck`, `npm test`, `build` kode 0; `v-html=` satu baris.
